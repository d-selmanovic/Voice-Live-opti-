# Modulzuständigkeit — geplant

| Modul | Zuständigkeit | Nicht zuständig für |
|---|---|---|
| conversation | aktuelles Gespräch und Ereignisse | dauerhafte Kundenprofile |
| runtime | Session, Jobs, Abbruch und Revision | ungeprüfte Geschäftsrechte |
| tools | Argumente, Ausführung, Wiederholung | unbeschränkte Recherche |
| policies | Rechte und Rückführung | willkürliches Smalltalk-Verbot |
| memory | kuratierte Kundeninformationen | Entwickler-Aufgabenliste |
| knowledge | freigegebene Firmenquellen | allgemeines Internetwissen |
| connectors | dienstspezifische Kommunikation | zentrale Rechte umgehen |
| config | validierter Agentenvertrag | Kundenidentität selbst bestätigen |
| prompts | kurze gemeinsame Gesprächsbausteine | technische Zugriffssperren |
| observability | IDs, Zeiten und technische Ergebnisse | ungeprüfte private Volltranskripte |

Module sind Verantwortlichkeiten, keine separaten Server. Die Referenzdemo ist zunächst gekapselt in browser_demo/ übernommen; diese Kunden-Core-Zuständigkeiten sind weiterhin geplant.
