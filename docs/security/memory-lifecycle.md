# Memory-Lebenszyklus — Entwurf

Memory pro Projekt aktivierbar, standardmäßig im Beispiel aus. Bei aktivierter Memory erst verifizierten Kundenkontext bilden. Neue Aussage mit Herkunft/Zeit und Zweck erfassen; nicht automatisch jede Gesprächsbehauptung übernehmen.

Vor dauerhaftem Schreiben Relevanz, Widersprüche, zulässige Daten und Firmentrennung prüfen. Kuratierung kann nach der Session erfolgen. Abruf nur relevant und innerhalb der Datenrechte. Memory ist beratender Kontext, keine höhere Autorität als aktuelle zulässige Nutzeranweisung oder feste Regeln.

Korrektur, Ablauf und Löschung inklusive abgeleiteter Suchindizes/Sicherungen konkret gestalten. Negative Fälle: falscher Kunde, manipulierte Anweisung, veraltete Sprache, Widerspruch und Löschen. S06/S15 unterstützen das Prinzip; Speicher und Schema noch offen.
